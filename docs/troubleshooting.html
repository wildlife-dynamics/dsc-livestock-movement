Troubleshooting

Common issues while configuring, running or changing dsc-livestock-movement, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

The run returns no data

Names typed into the settings (a subject group, an event type) must match the data source exactly, including capitals. Widen the time range if it's short.

The report

The run fails with a missing column: Community/Zone, FROM or TO

The columns are named by the field titles of the livestock_block_movement event type. If a title was changed in EarthRanger, change it back, or update the column names in spec.yaml and recompile.

The table is empty

There are no livestock_block_movement events in the time range on that site. Check the range and the data source.

A movement that looks right is a Missed movement

It's compared with the movement before it by time, named in its status. Check that movement: a wrong date, often a year typo, puts it out of order, and a movement between the two may not have been entered.

Every Community/Zone starts with a First record

The first movement in the time range has nothing before it to compare with. Start the range before the survey you want to check.

Developing

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-dsc-livestock-movement-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
