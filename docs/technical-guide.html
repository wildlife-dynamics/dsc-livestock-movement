Validate Block Movements

validate_block_movements (in ecoscope-workflows-ext-distance-sample-counts) needs the columns Community/Zone, time, date, serial_number, FROM and TO (lists of blocks). It sorts by Community/Zone and time, compares each movement's FROM with the previous TO in the same Community/Zone (as sets, so order doesn't matter), and adds status, is_issue, prev_serial, prev_date and expected_FROM. Every movement is returned, not only the issues.

The column names come from the event type's field titles (process_events_details with map_to_titles: true), and get_events runs with include_display_values: true, so the blocks are shown by their display names.

Recompiling

spec.yaml is the source; ecoscope-workflows-dsc-livestock-movement-workflow/ is generated from it by wt-compiler.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh dsc_livestock_movement --all
